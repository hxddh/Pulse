# 2.1 计划 —— Evidence / 证据

## 1.1 算出来的东西，大部分从没露过面

1.1 让采集器读完整份笔录并把结果存进会话摘要。摘要里现在躺着：

| 事实 | 1.2 之后的去向 |
| --- | --- |
| 精确记录数 | 上了行 |
| 工具直方图 | 上了 Details |
| 错误总量 | 上了 Details |
| 打转（同一工具连续 N 次） | 上了叙事行 |
| **最近工具序列（有序，≤12）** | 只用来判断打转，序列本身从没显示 |
| **整场会话 token** | 算了、存了、**没有任何界面读它** |
| **追平进度 / 是否已读完** | 只进支持报告 |
| **会话真实起点**（`firstFoldedMs`） | 没用 |
| **笔录增长速率** | 没算过 —— 但每次扫描都已经知道 size 与上次 offset 的差 |

用户的原话是「基本没有太多有效信息」。看着上面这张表，这句话是对的：产品**采集**的深度远超它**说出**的深度。

## 这一版顺手改掉了「最多 4 个事实」

本版原计划守着 `EXPERIENCE` §4 的「一条静态行最多 4 个事实」，把所有新事实都放进
Details。**这条规则被推翻了，理由在文档自己身上。**

它写于「两行三级文字塞了 10 个并列事实」的事故，是一次反向矫正；文档紧接着就
自述「然后**矫枉过正**：到 0.27 每行只剩 2 个事实，而且两个都是静的……面板因此
只在被追问时才可观测」。那个 4 是从事故里反弹出来的数字，不是推导出来的。

真正该防的是**无差别的平铺清单**——读起来像枚举，扫视成本按条数线性上升。
而**四个静事实（标题、路径都不随干活而变）比六个里有两个在动更难回答
「它推进了吗」**。所以约束从「几个」换成「哪几个、怎么排」：

- 动态事实优先于静态事实竞争位置；
- 每个事实此刻必须有值（0 / 未知 / 与相邻行重复的不出现）；
- 条数随内容浮动，但不得增加行高，拥挤时收敛，Waiting 时让位给等待详情；
- 趋势图 / 历史曲线 / 统计大盘 / 同一事实换个口径说第二遍 —— 仍然禁止。

**完整证据仍然进 Details**（EXPERIENCE 本来就把它定位在详情审视器），
但行不再因为一个数字上限而把已经知道的事憋着。

## 一处被闸门挡住的事实（本版的技术重点）

搬运点现在是：

```swift
if let digest, digest.caughtUp, digest.records > 0 {
    records = digest.records
    digestFacts = digest        // ← 全部定性事实一并被 caughtUp 挡住
}
```

`records` 要求 `caughtUp` 是对的：数窗口里的换行只是**下限**，而「数量不估算」是硬规则。
但工具直方图、错误数、最近工具、token **不是估算** —— 它们是「到目前为止已经读到的」，
且摘要自带 `progressPercent` 可以自证完整度。

后果恰恰最伤：**一个跑了很久、正在追平的大会话，是最需要信息的时候，却什么都不显示。**

本版解耦：`records` 保留 `caughtUp` 闸门；定性事实照常流出，**界面有义务标注
「仍在追平 · 已读 78%」** —— 披露过的部分值不是估算，藏起来才是浪费。

## 逐项清单

### P0

| ID | 项 | 验收 |
| --- | --- | --- |
| P0-1 | 增长速率 | `SessionDigest` 记住上一次的 (size, foldedMs)，给出 `bytesPerMinute`；时间差 < 5s 或 compaction 一律报 0（不知道就说不知道） |
| P0-2 | 解耦闸门 | 定性事实不再被 `caughtUp` 挡住；`records` 仍然要求它。回归测试钉住「未追平时 records 仍是窗口值，但工具/错误/序列有值」 |
| P0-3 | 契约搬运 | 七个新字段 `Fact → Row → AgentRow` 三层**只搬运不重算**；merge 里 `sessionStartedMs` 取 min（更早的才是起点），其余取 max |
| P0-4 | Details 证据卡 | 最近动作时间线、整场 token（**明确区别于「最近一条消息」token**）、活跃度、会话时长、读取完整度 |
| P0-5 | 行按信息量取事实 | 改写 EXPERIENCE §4：动态优先、0/未知不出现、条数浮动、不增行高、Waiting 让位；回归测试钉住排序与「无值不显示」 |
| P0-6 | 场景 AS + 测试 | EXPERIENCE **AS**；`EvidenceSurfaceTests` + digest/ground-truth 回归 |

### 明确不做

| 项 | 理由 |
| --- | --- |
| 统计大盘 / 图表 / 趋势线 | 那是另一个产品，非目标里写着 —— 去掉的是条数上限，不是这条 |
| 无差别平铺成枚举清单 | 这才是当年那次事故的真正内容 |
| 把摘要事实拿去改灯色 | 状态编码上限 4 种；发明第五种要单独论证 |
| 从窗口文本复核摘要 | 窗口没读过那些字节，复核只能是猜（1.2 立的纪律） |
| 存正文 / 工具入参 / 笔录里的路径 | 0.99「数据静默」的边界不动：只存计数与厂商工具名 |

## 一条新的诚实条款

**披露的部分值 ≠ 估算。** 本版第一次让「还没读完的事实」上界面，代价是界面必须
说出它还没读完。做不到标注的地方，宁可不显示 —— 那才是回到「把下限当总数」的老路。
