# 1.0 计划 —— Remote Fleet / 我的舰队

## 为什么这一版是 1.0

到 0.99.2 为止，`1.0` 这个号被「已公证」占着。那是**分发属性**，而且外部 blocked（没有
Apple Developer ID）—— 结果是这个号永远标不了任何产品里程碑，而产品已经走了十版。

本版把它解绑：**1.0 归产品，渠道诚实交给 `PulseDistributionChannel`。** About 照旧显示
`preview`，DMG 照旧是 ad-hoc/未公证，发布说明照旧写明「不是 Gatekeeper-ready」。
**解绑的是版本号的含义，不是任何一句关于签名的承诺。**

## 这一版换的是分母

0.90–0.99.2 连续十版都在同一个问题上：**让 Pulse 说的话等于它知道的事**。做对了，
但它们没有改变 Pulse **能知道什么**。

产品第一句话是「扫一眼知道编码 Agent 要不要你」。实际交付的是「……只要它跑在这台
Mac 上」。云端会话、远程开发机、devcontainer、CI 里的 agent —— 一个都看不见，
而且**看不见的时候灯是绿的，不是灰的**。这是这个仓库最不能忍的那种谎，只不过它
一直藏在能力边界里，而不是藏在某个函数里。

`docs/plan-0.23.md` 的「明确不做」早就点名了这件事：

> 远程 / devcontainer agent 可见性 | **真正的能力边界**（Pulse 只看本机进程与文件），
> `attention.tsv` 已是现成抓手，但改动大，**等核心有测试再说**

那不是非目标，是**附条件推迟**。条件（核心有测试）在 0.23 之后就陆续满足了：
526+ 测试、七道门禁、逐 Agent 的 fixture 断言、十版诚实工程。**欠款到期。**

## 为什么现在做代价可控

硬的部分已经建好并测过 —— 「一盏由外部事件点亮、且不会被点假的灯」已经存在：

| 已有能力 | 位置 |
| --- | --- |
| 公开事件协议：TSV、kind 白名单、厂商别名归一、拒绝自由文本 Waiting | `AttentionProtocol` / `docs/attention-protocol.md` |
| **没有匹配行时自己建行** | `SnapshotBuilder` 的 `.unmatched` 分支 |
| flock 并发写、80 行压缩且保留未决 raise | `AttentionIO` |
| 边沿去重、通知、稍后、清除、durable 账本 | `AttentionLedger` |
| 文件变化近实时刷新 | `AttentionWatcher` |

缺的只有三样：**字节从哪来**、**这是哪台机器**、以及最难的 **远端行怎么诚实地熄灭**。

**Pulse 不写网络代码。** 传输是用户自己的：`attention.d/` 收件箱目录，谁往里放文件都行
—— rsync、syncthing、iCloud、挂载卷、你自己 ssh 跑的一行脚本。不联网、不带服务器、
不上传任何东西：「无遥测」这条承诺字面意义不变。

## 设计

### 协议 v2：加一列 `host`

```text
# pulse-attention v2 (agent\tkind\tms\tmessage\tsession\tcwd\thost)
```

v1 的六列行**仍然合法**，`host` 视为空 = 本机。已安装的旧 `pulse_hook.py` 写的 v1 头
必须继续能读 —— 升级不能让本机的灯灭掉。

### 收件箱：`attention.d/`

Pulse 读本机的 `attention.tsv`（不变）**加上** `attention.d/*.tsv` 里的每个文件。
一台远端机器一个文件，互不加锁竞争。有界：最多 16 个文件、每文件沿用 80 行压缩、
单文件超限按既有规则保留未决 raise。

### 身份：两台机器的 Claude 不能撞在一起

`host` 进 `Entry.mapKey` 与远端行的 `rowKey`。snooze / dismiss / 通知去重全都跟着
`rowKey` 走，撞车等于按错人。身份行显示来源机器。

### 远端行的诚实（本版的真正难点）

本机行的活性来自进程探针与文件 mtime。远端行**什么都没有**，只有「最后一条事件」。
所以：

| 规则 | 理由 |
| --- | --- |
| 远端行**永不** `liveProcess` | 没有探针证据。写成绿灯就是发明事实 |
| 远端行**没有 Focus 按钮** | 聚焦不了另一台机器。给一个点了没反应的按钮比不给更糟 |
| 次行说「**最后听到 N 分钟前**」，不说「最近活动」 | 我们知道的是收到过什么，不是它在干什么 |
| 超过 TTL 未刷新 → **失联**，不是消失 | 本机行消失有探针作证；远端行消失只是猜。红灯必须撤，行必须留，并说明为什么 |

失联是这一版新增的唯一状态，它的存在正是为了**不**把「我不知道」显示成「它结束了」。

### 时钟

`tsMs` 来自另一台机器。现有 `AttentionReader.parse` 会**静默丢弃**未来超 5 分钟或早于
TTL 的行 —— 对本机这是对的，对一台时钟偏 20 分钟的远端机器，这意味着它的等待
**永远不出现，且没有任何提示**。

- 记录 `receivedAtMs`（Pulse 第一次看到该行的时间）。
- 事件时钟不可信时（相对接收时间越界），用接收时间排序与计时，并在 Details 里
  **说明用的是哪一个**。
- 远端行被时钟规则丢弃时**必须留痕**（安全支持报告 + debug.log），不允许静默。

### 明确不做（四条旧禁令重评后的结论）

| 项 | 结论 | 理由 |
| --- | --- | --- |
| 托盘内 approve / deny | **推迟到 1.1，不是永久否决** | 它改的是动词，值得做。但现实上只覆盖有阻塞 hook 面的 2 个 Agent，且要反转 `PulseHookReceiver` 里「绝不卡住 Agent」这条安全属性。做错了不是灯不准，是**卡住你真正在干的活**。而且 1.0 会顺路铺好它需要的管子（host 身份 + 双向就绪的收件箱），先做远程更省 |
| 配额 / 费用 HUD | **不做，理由换成能力** | 账号级配额要厂商 API + 凭证 + 联网，三样 Pulse 都刻意没有。**会话级成本已经做了 90%**（`usage` / `last_token_usage` / `agent_usage` 进观测行）——「这个会话烧了多少」有，「这个月还剩多少」没有 |
| 继续扩 agent 名单 | **维持不做** | 四条里唯一有硬证据的：fixture 墙覆盖不到 32 个以外，而 0.96.1–0.97.2 四连发证明了「没有可验证覆盖的 Agent = 抽奖」 |
| 上传遥测 / 自建服务器 | **维持不做** | 传输由用户提供，Pulse 不联网 |

另：假 Waiting、cache→session 升格、统计大盘、凭猜修解析 —— 一律不变。

## 已知缺口（先写下来）

1. **P0-3 解析缺口仍空着。** 与本版无关但仍未清：需要装了 Agent 的真机产出
   explain / shape。0.99.2 已把取证成本降到一次点击，但**降低成本不等于拿到证据**。
2. **远端行的事实深度天然浅。** 它只有 raise 里那 ≤200 字消息、session、cwd —— 没有
   会话记录、没有 model/tokens、没有活动时钟。托盘必须把它显示成「浅」，而不是用本机行的
   模板去套一个空壳。
3. **时钟规则是启发式。** 「事件时间不可信」只能靠与接收时间的偏差判断；一台偏移
   稳定的机器无法与「事件确实发生在 20 分钟前」区分。所以规则的输出必须**可见**，
   由用户判断，而不是由 Pulse 悄悄选一个。

## 为什么是这个顺序

先协议与收件箱（P0-1/P0-2），因为身份与诚实规则都挂在它们上面；再身份（P0-3），
因为撞车会毒化 snooze/dismiss/通知去重这些已有的正确行为；最后才是远端行的诚实
（P0-4/P0-5）—— 那是本版真正的产品价值，也是唯一一处「做错了会让 Pulse 重新开始说谎」
的地方，值得放在地基铺好之后再动。
