# Pulse 0.24.0 计划 — 「一眼看出该管谁」

0.22 补功能，0.23 补可信度。这一版补**辨识度**。

## 主张

Pulse 现在能告诉你「有东西在等你」。它还不能告诉你**等的是哪一个、等了多久、
该先管谁**。三个 agent 同时红灯时，托盘给出的三行长得一模一样。

一句话：**从「有人在等」到「先去看这个」。**

---

## 现状诊断（都能在代码里指到）

### 1. 一行最多塞 10 个事实

`EXPERIENCE.md` §6 自己写着「一行一个意思」。实际上一条运行中的行是：

```
hero          Refactor the snapshot builder
agentLine     Claude · Pulse · ×3 · Warp · hooks          ← 5 个事实
metaLine      ↑1.2k ↓340 · Edit · planning · sub 2↑ · a3f9c1  ← 5 个事实
```

`agentLine`（`PulseApp.swift:501`）和 `metaLine`（`Models.swift:292`）各自用 ` · `
拼接最多 5 段。两行 11pt / 10.5pt 的三级文字里挤了 10 个并列事实，
没有一个能被扫到。**这是辨识度最大的敌人**：不是信息太少，是没有主次。

### 2. 一行的状态有 8 种并行编码

同一条行的状态同时由这些东西表达：

| 编码 | 取值 |
| --- | --- |
| 左侧色块 | 8pt / 0pt |
| 行底色 | `waitAccent.opacity(0.10)` / clear |
| 图标透明度 | 0.55 / 1.0 |
| 标题字号 | 12.5 / 13.5 |
| 标题字重 | medium / semibold |
| 标题颜色 | primary / secondary |
| StatusChip | 4 种 |
| 整行透明度 | 0.82 / 1.0 |

8 种编码表达大约 4 个状态。冗余不等于强调 —— 每多一种编码，
其余每一种的信噪比就低一点。**精致感的对立面不是简陋，是这种到处都在喊的状态。**

### 3. 「等了多久」是最该看见的信息，现在藏在第三行

`waitSinceMs` 一直在采集，`waitDurationLabel()` 也早就写好了，但它唯一的出口是
`localizedWaitDetail()`（`StatusStore.swift:628`）拼出来的：

```
↳ 12分 · hooks: Grant file write access?
```

11.5pt，第三行，和信号来源、原始消息挤在一起。而**「等了 12 分钟」恰恰是决定
先管谁的那个数**。等 30 秒和等 40 分钟在当前 UI 里长得一样。

### 4. `headerDetail` 恒为「刚刚」

`SnapshotBuilder` 在 `snap.updatedAt = Date()` 之后立刻算 `relative(updatedAt)`，
差值恒 < 5 秒。头部第二行是个常量。（0.23 已记录，仍未修。）

### 5. 面板高度是手算的魔法数字

```swift
var h: CGFloat = 44
if row.waiting { h += 20 }
if row.isProcessOnly { h -= 4 }
if row.metaLine != nil { h += 14 }
if row.waiting || row.canFocusTerminal || row.canOpenFolder { h += 28 }
return h + 8
```

`PulseApp.swift:362`。任何字号、行距、内容变化都会让面板高度和内容对不上。
**这是「精致」在工程上的具体障碍**：布局是猜的，不是量的。

### 6. 排序做了，但没有可见的结构

Waiting 排在最前，可视觉上 5 行是一个无差别的堆栈 —— 没有分组表头，
看不出「上面 2 条是要你处理的，下面 3 条不用管」。

## P0 — 辨识度（这一版的主线）— ✅ 已完成

### 1. 等待时长升格为主信息

- 徽章从 `需要你` 变成 `需要你 · 12分`，等待时长和状态词同级；
- Waiting 行内部**按等待时长倒序**（最久的在最上）；
- 超过阈值（建议 10 分钟）视觉升级：左色块加宽、颜色加深 —— **只有这一处**
  用"更响"来表达"更久"，不再叠加别的编码；
- 菜单栏在 waiting 时显示最久的那个等待时长，而不是 agent 名。

数据已经有了，`waitSinceMs` / `waitAgeSeconds` / `waitDurationLabel` 全是现成的。
这是投入最小、辨识度收益最大的一项。

### 2. 分组表头

```
需要你 · 2
  ● Grant file write access?        Claude · Pulse        12分
  ● Continue with plan?             Codex · api           2分
运行中 · 3
  ○ Refactor the snapshot builder   Claude · Pulse
  …
最近
  …
```

把不可见的排序变成可见的结构。这是 Things / Linear / Raycast 都在做的事：
**分组表头比任何行内样式都更能降低扫描成本**。

### 3. 每行最多两行文字

- 第一行：任务标题（hero）
- 第二行：`Agent · 项目`（**最多两个事实**）
- tokens / tool / skill / sub / sessionHint 收进悬停浮层或展开态

现在的 `metaLine` 直接删掉不显示在静态行里。信息不丢，只是不再和主线抢。

### 4. 菜单栏计数

Waiting 时菜单栏显示 `● 3`（现在 `snap.title` 已经是计数或 agent 名，
但没有视觉层级）。让「有几个在等」在不点开的情况下就成立。

## P1 — 精致感与优雅 — ✅ 已完成

### 5. 用真实布局替代 `estimateHeight`

改用 `ScrollView` + 内容自然高度 + `frame(maxHeight:)`，或测量后再定高。
面板高度不该是加减法猜出来的。**这一项不做，后面所有排版调整都会是打地鼠。**

### 6. 状态编码从 8 收敛到 3

保留：左色块（是否需要你）、徽章（状态 + 时长）、标题字重（是否有真实会话）。
删除：行底色、图标透明度、整行透明度、标题字号差、标题颜色差。

### 7. 动效克制

- 菜单栏图标的永久呼吸改成**新等待出现时闪一次**，之后静止
  —— 永久动画在菜单栏是噪音，且和"等了多久"无关；
- 行的进入/退出用 `.transition`，不要整列跳变。

### 8. 4pt 栅格

现在的 padding 是 14 / 10 / 9 / 11 / 8 / 2.5 / 26 混用。统一到 4 的倍数，
字号统一到 4 档（13.5 / 12.5 / 11 / 10.5 → 13 / 12 / 11）。

是设置页「最近的等待」区里的一行摘要。

### 12. 可选提示音

新 Waiting 时的一声轻提示，默认关。

## 验收

- 三个 agent 同时等待时，**1 秒内**能说出该先管哪个（现在做不到）；
- 一条静态行最多两行文字、最多 4 个事实（现在最多 10 个）；
- 面板高度由内容决定，不含手写的高度加减法；
- 状态编码 ≤ 3 种；
- `headerDetail` 要么携带真实信息，要么删掉；
- `EXPERIENCE.md` §4 与实现一致 —— 这一版要求先改规格再改代码。

## 风险

- **这是这个产品第一次大改视觉**。`EXPERIENCE.md` 是 UI 改动的验收依据，
  所以规格要和代码一起改，否则又会出现「文档描述的是另一个产品」的老问题。
- 视觉改动在本仓库**没有自动化验收手段** —— 测试覆盖不到布局。
  建议每一项配一张前后对比截图，人工过。
- P1-5（真实布局）会动到 `agentList` 的高度逻辑，是本版风险最集中的一处，
  建议单独一个提交、单独验证。

## 实现记录

### 与计划的偏离

**菜单栏时长做了「够久才显示」的处理。** 计划写的是「waiting 时显示最久的等待时长」。
直接照做的结果是：等待 1 秒时菜单栏显示 `now` —— 比原来的 `Claude…` 信息量更低，
而且灯本身已经说明了这件事。有两个既有测试正好钉住了这个行为，把问题挡了下来。

改成随时长升级：`Claude…` → `Claude · 4m`，多个等待时 `2` → `2 · 12m`。
5 秒以内不占这个位置。

**「跳到等待最久的」是托盘内动作，不是全局快捷键。** 计划写的是「一键从任何地方」。
`GlobalHotKey` 目前只注册一个热键、回调写死为 `TrayReveal.show()`，
加第二个需要改注册与分发逻辑。现在的实现是托盘里的 `⌘J`，
外加通知点击本来就会聚焦到等待的 agent。**这一项没有完全兑现计划的措辞。**

**没有做前后对比截图。** 计划的风险一节要求每项配截图人工过。
这个容器没有 macOS，没法截图 —— 布局与观感**完全未经人眼验证**，
只有编译和单元测试的保证。这是本版最大的未知。

### 顺带修掉的

- `headerDetail` 恒为「刚刚」：改为显示涉及的 Agent 名（最多 3 个），
  并把 `Context.relativeLabel` 一并删掉 —— 一个只能产出常量的参数。
- `DurationFormat` 从 `StatusStore` 的实例方法提出来，
  否则纯函数的 `SnapshotBuilder` 没法给菜单栏算时长。
