# 2.6 计划 —— Effect / 成效

## 一件事：读工作区，不读厂商

Pulse 今天的证据只有两类：**agent 自己写下的东西**（笔录、缓存）和**进程还活着没有**
（`ps`）。两类都在回答「它在干什么」。

第三类一直摆在那儿没人碰：**盘上到底变了什么。**

---

## 为什么是这条轴

### 能力

| | 今天 | 之后 |
| --- | --- | --- |
| 证据来源 | 厂商写的文件 + `ps` | 加上**磁盘本身** |
| 能不能被伪造 | 笔录是 agent 的自述 | **改了就是改了**，没有自述的余地 |
| 覆盖 | 32 个 adapter，逐家手写 | **零 adapter** —— 工作区不属于任何厂商 |
| 依赖 | 厂商格式，随时会变 | git 的 porcelain 输出，为脚本冻结 |

这是第一条**不随厂商数量增长的证据轴**。S1（声明式 adapter 契约）那笔债之所以一直在，
是因为每加一家就要加一份解析；这条轴一份都不用加。

### 产品

产品到现在能回答「它在跑」「它在等你」「它在算」（2.2）「它在产出笔录」（2.1）。
**它一次都没能回答「它干成了什么」。**

- 行上第一次有落地的量：`7 个文件 · +142 −38`
- 「忙」和「有产出」第一次分开 —— CPU 高、笔录在长、**盘上没动**，这是 agent 原地打转
  最诚实的画像，比 1.2 的 loop 计数强一个量级
- **只有 Pulse 能看见的那件事**：两个 agent 在同一个工作副本上。每个 agent 只知道自己；
  这个碰撞今天没有任何工具看得见，而它正在悄悄毁掉别人的改动

### 为什么不是厂商侧那条

判决通道现在只运一个 bit。二进制证据里 decision 对象是
`{behavior, updatedInput?, message?, interrupt?}` —— 理论上能回的不是「不行」，
而是「不行，改用 `make clean`」。那才是人真正想给的答案。

但它和「判决的第三种下场」卡在同一件没验的事上：**厂商拿到我们发的东西之后到底做了
什么。** 2.5 刚立的规矩是「假设它在，就是在犯本版要修的错」，不能一边写规矩一边靠它
开工。本版把取证脚本写进 `scripts/`（见先决门槛），跑过之后 2.7 才谈得上。

## 怎么测

三条命令，全部 `--no-optional-locks`：

| 命令 | 取什么 | 频率 |
| --- | --- | --- |
| `rev-parse --show-toplevel` | 规范化的仓库根 —— 碰撞判定要它 | 每个 cwd 一次，长缓存（它不会变） |
| `status --porcelain=v1` | 变动路径数（含新建文件） | 按节奏 |
| `diff --shortstat HEAD` | 文件数 / 增行 / 删行（已跟踪部分） | 按节奏 |

**`--no-optional-locks` 不是可选的。** `git status` 默认会刷新并**写回** index 的
stat 缓存 —— 那会违反「只读」，还会和用户自己的 git 命令抢 `index.lock`。这个 flag
的存在理由正是编辑器/状态栏这类旁观者。

## 硬规则

1. **只读，永不写。** 不 `add`、不 `stash`、不碰索引。除上表三条之外一条都不跑。
2. **只取计数，不取内容。** 文件数、增删行数、脏不脏。**不要 diff 正文、不要文件路径**，
   支持报告照样过 `ContentSanitizer`。
3. **未知是 -1 不是 0。** 不是 git 仓库、超时、命令失败 —— 一律「不知道」。
   「测了，没动」和「没测」是两个答案（2.2 为 CPU 立的规矩，这里照搬）。
4. **省电是硬约束，这条最容易翻车。** 走 `ProcessIO.run` 的有界超时；按 harvest 的
   节奏跳拍而不是每拍都跑；**同一个工作区多行只测一次**；一个工作区测得太慢就进退避，
   并如实报「不知道」。
5. **`cwdBestEffort` 没确认过的路径不测**（2.2 已立：解对了和解错但碰巧存在分不出来）。
6. **不做趋势图、不做提交历史、不显示分支名。** 前两个是非目标；分支名是内容，不是计数。

## 逐项清单

### P0 · 测量

| ID | 项 | 验收 |
| --- | --- | --- |
| W-1 | 纯解析 | `shortstat` 三种残缺形态（只有增 / 只有删 / 只有文件数）、`porcelain` 计数含 `??`；解析失败一律 -1 |
| W-2 | 有界执行 | 超时走 `ProcessIO.run`；非零退出 = 不是仓库 = 未知；stdout 上限 |
| W-3 | 每工作区一次 | N 行共用一个根，一拍只测一次 |
| W-4 | 慢仓库退避 | 单次测量超过预算 → 该根进退避，期间报未知；退避可恢复 |
| W-5 | 节奏 | 不每拍跑；跟随 harvest 的跳拍规则；息屏停表照旧 |
