# Pulse 0.25.0 计划 — 「每一行都值得占那个位置」

0.24 解决的是**一行塞了 10 个事实**。真机截图显示，现在的问题正好相反：
**少数几个事实被重复说了三四遍**，而真正有用的信息一个都没有。

---

## 真机证据（0.24.0 截图）

两个 agent 在跑，面板高度约 600pt。上面写了什么：

```
菜单栏   ⊙ 2
头部     2 个运行中
         Cursor · Amp
分组     运行中  2
行 1     [icon] Pulse installation guide        [运行中]
                Cursor · Cursor
行 2     [icon] 检测到进程                       [进程]
                Amp
动作     刷新 / 偏好设置… / 退出 Pulse
页脚     Pulse 0.24.0            复制诊断信息
```

### 1. 同一个事实说三到四遍

**行 2 携带的全部信息是「Amp 有个进程在跑」**，而它被说了四次：
标题「检测到进程」、芯片「进程」、次行「Amp」、（按项目分组时）表头「Amp 1」。

**「运行中」这件事说了三次**：头部「2 个运行中」、分组表头「运行中 2」、
每行的芯片「运行中」。

0.24 把「一行 10 个事实」压到了 4 个，但没检查**这 4 个是不是同一个事实**。
辨识度没有提升，只是把噪音换了一种形式。

### 2. `Cursor · Cursor`

次行去重只和标题比过，没和 Agent 名比。项目目录恰好叫 Cursor 时就并排显示两次。

### 3. 分组表头在只有一组时是纯冗余

头部刚说完「2 个运行中 / Cursor · Amp」，下一行分组表头再说「运行中 2」。
按项目分组时更糟：项目为空退化成 Agent 名，于是表头「Cursor 1」「Amp 1」
和每行次行完全重复。

### 4. 切换语言后行内文字不跟随（已修）

截图 2 里外壳是英文、行内是中文。`AgentRowButton` 用的是 `let store`
而非 `@ObservedObject`，不订阅变更，SwiftUI 判定输入未变直接跳过重绘。
**这个 bug 早于 0.24，一直都在。**

### 5. 真正缺的信息一个都没有

「Pulse installation guide」在**哪个目录**？跑了**多久**？上次动静是**什么时候**？
—— 一个都没有。面板花了 600pt，没回答「我该不该管它」。

---

## 主张

**每一行都要为自己占的那个位置付账。** 判断标准只有一条：
去掉它，用户的决策会不会变？不会，就删掉。

0.24 问的是「这行有几个事实」，0.25 要问的是「这行有几个**不重复的、能改变决策的**事实」。

---

## P0 — 信息效率

### 1. 全局去重规则（写进 EXPERIENCE.md，做成可检查的约束）

同一事实在面板里**只允许出现一次**，优先级：**行内 > 分组表头 > 头部**。

- 头部只在**行内说不清**时才说话（比如被折叠的行、全局错误）
- 分组表头只在**多于一组**时出现（已修）
- 行内芯片与标题不得表达同一件事

### 2. 行的信息重排

| 位置 | 现在 | 改成 |
| --- | --- | --- |
| 标题 | 会话标题 / 「检测到进程」 | 会话标题；无标题时用 **Agent 名**（已修） |
| 次行 | `Agent · 项目`（常重复） | **项目路径 + 相对时间**（`~/code/Pulse · 12分钟前`） |
| 芯片 | 状态词（与头部重复） | 只在**非常态**时出现：等待中 / 无信号 / 异常 |
| 图标 | Agent 品牌标 | 不变（它替代了次行的 Agent 名） |

关键：**Agent 身份交给图标**，次行腾出来放真正缺的「哪里 + 多久」。
运行中是常态，不需要每行贴一个绿标签——**没有芯片就是运行中**。

### 3. 头部瘦身

只有一组时头部与分组表头二选一。建议保留头部、去掉表头（已修），
并把头部次行从「涉及的 Agent 名」（行内已有）换成**更高层的信息**：
最久运行时长 / 是否有被折叠的行 / 探测异常。

### 4. 空间预算

面板 600pt 只承载 2 行内容，头部 + 表头 + 动作 + 页脚占了约 70%。
目标：**同样 600pt 至少容纳 6 行**。动作区改为一行图标条，页脚并入动作区。

## P1 — 精致感

### 5. 排版

- 行高统一到 4pt 栅格，标题/次行 13/11，行距固定
- 图标尺寸与标题基线对齐（现在略高）
- 分隔线只在分组之间，不在行之间

### 6. 空态与单行态

只有一个 agent 时不该看起来像一张表格。单行时收起分组、收起表头。

### 7. 悬停反馈

现在悬停只是让操作条出现，行本身没有任何反馈。加一层极轻的背景。

## P2 — 产品功能

### 8. 项目 / 目录是一等公民

`cwd` 一直在采集但几乎不展示。次行放它，并支持按目录聚合
（比按 Agent 聚合更贴近「我在做哪几件事」）。

### 9. 运行时长

`harvestMs` 有了但没用于展示运行时长。「跑了 20 分钟没动静」是一个真实信号，
和 Waiting 一样值得看见。

### 10. 单会话展开

点击行展开：完整任务标题、tokens、tool、子任务、session id ——
0.24 把这些塞进了悬停浮层，浮层放不下也不可复制。

### 11. 「刚才发生了什么」

面板只显示当下。回来时最想知道的是「我离开这段时间发生了什么」。
用已有的 wait history + 状态变迁，给一条时间线。

## 验收

- **同一个事实在面板里只出现一次**——拿截图逐项数，重复即不通过
- 600pt 面板至少容纳 6 行
- 每行都能回答「在哪里、多久」，而不只是「谁、什么状态」
- 单 agent 时面板不出现分组结构
- 切换语言，**行内文字立刻跟随**（0.24 的回归测试）

## 风险

- **仍然没有自动化的视觉验收手段。** 0.24 的教训是：编译通过、142 个测试全绿、
  规格同步更新，界面照样不对。这一版必须**先出截图再合并**，
  否则就是重复同一个错误。
- 「没有芯片就是运行中」是个反直觉的设计赌注，需要真机确认可读性。

## 实现记录

P0 / P1 / P2 已实现，CI 全绿（156 个测试、打包 + selftest 通过）。

### 关键改动

| 项 | 结果 |
| --- | --- |
| 语言 bug | `AgentRowButton` 改 `@ObservedObject`（**早于 0.24 就存在**） |
| 次行 | `Agent · 项目` → `~/code/Pulse · 12 分钟前` |
| 芯片 | 运行中不再发芯片；只有等待 / 进程 / 最近 / 子任务发 |
| 头部次行 | 只说聚合：折叠数、跨项目数；单项目时**沉默** |
| 动作区 | 5 行菜单 + 页脚（约 170pt）→ 一条图标栏（约 34pt） |
| 详情 | 悬停 tooltip → 行内展开，**可选中可复制** |
| 分组 | 按项目分组改用真实路径，不再退化成 Agent 名 |
| 行间分隔线 | 删除，只在分组间保留 |

### 写代码时发现自己的规则是错的

头部「只说聚合」的第一版实现里，单个项目时返回该项目路径 ——
**而每一行下面都写着同一个路径**。这正是这一版要消灭的重复，
在修复它的代码里原样复现了一次。改成单项目时返回空串。

值得记下来：**去重规则很容易在写的时候就被自己破坏**，
所以验收必须对着截图数，不能靠读代码。

### 仍未兑现

- **截图验收没做到。** 计划的风险一节写着「先出截图再合并」，
  而这个容器没有 macOS。0.24 的教训（编译过、142 测试全绿、规格同步、界面照样不对）
  **在这一版原样成立**。
- 「没有芯片就是运行中」是设计赌注，需要真机确认可读性 —— 未验证。
- 空间目标「600pt 装 6 行」是按静态高度估算的，**未实测**。

## 0.25.0 真机截图复盘（→ 0.26 修复）

发布后的真机截图暴露了七个问题，其中最重要的一个是**这一版新写的规则被这一版自己破坏**。

### 去重规则只用在了一半的地方

规则写的是「行内 > 分组表头 > 头部」，实现时只修了**面板头部**：

```
~/Documents/Cursor   1        ← 表头
  Pulse installation guide
  ~/Documents/Cursor · 4m ago ← 同一条路径，原样再说一遍
```

按项目分组时每条路径出现两次；单行分组的表头更是纯粹把那一行的路径单独占一行。

**教训**：规则写完的下一步必须是逐处对照。它只在写它的那个地方成立，
而「我记得我修过」不是证据。

### 家目录被当成了项目，而且是两个

`~` 和 `users-rustjia` 是同一个目录：前者来自 `cwd`，后者来自没有 `cwd` 时
回退的编码 `project`。于是同一个位置分成两组，头部还据此报了「3 个项目」——
实际只有 2 个。

### 其余五处

| 问题 | 表现 |
| --- | --- |
| `Doing` 与 `Recent` 互斥 | 前缀恰好在**不活跃**时才加，和芯片自相矛盾 |
| `New Session` 当标题 | 占位符不在 junk 名单里 |
| `54s ago` | 面板几秒一刷，秒级精度是假的 |
| 标题断在词中间 | `Review repository for bugs a…` |
| 头部说 2、列表 4 行 | 头部只数运行中，不数最近 |

### 新增信号：停滞

`harvestMs` 一直在采，但「跑了 20 分钟没有任何动静」从未被表达过——
它和 Waiting 一样是真实信号，而界面把它显示得和健康会话一模一样。

实现时先写成了计算属性调 `Date()`，而它所在的 builder 是靠注入 `nowMs` 的纯函数，
固定时钟的测试里每一行都「停滞了好几年」。这和 0.23 把 `focusTier`
移到扫描时是同一个错误，已改为扫描时求值的存储字段。
