# 0.99.2 计划 —— Live Wire / 通电

## 这一版为什么存在

0.99.1 的结论是「探针从来没通过电」。修好解析之后该问的下一个问题不是「还有什么别的
bug」，而是**这条线上还有没有第二个断点**，以及它真正通电之后，下游那段从没运行过的
代码会不会做错事。

两个断点都找到了，第一个有实测证据。

无 Apple Developer ID → Stable Gate 仍外部 blocked；**不跳 1.0**。

**诚实前提：**

- 不伪造 Waiting；不扩 hooks；不升格 cache→session。
- builder 保持纯；无额度 HUD；托盘无 approve/deny。
- **不凭猜修解析** —— 仍等 P0-0 真机证据（见下）。

## 现状盘点（0.99.1）

| 主题 | 缺陷 | 0.99.2 动作 |
| --- | --- | --- |
| lsof 退出码 | `ProcessProbe.shell` 要求 `status == 0` 才返回输出。实测：批里有一个 pid 已退出 → lsof **退 1 但照常打印其余进程**。于是整批被丢 → `paths` 空 → **5 分钟全局 backoff + 每个 pid 负缓存**。一个 Agent 会话结束能让另外几个 Agent 的工作区消失五分钟 | 输出与退出码分开判断；backoff 只在 lsof 真不可用时武装 |
| 超时后读退出码 | `ProcessIO.run` 超时 → `terminate()` → 等 0.5 s → **无条件**读 `terminationStatus`，而它只在子进程已退出后有定义。SIGTERM 是请求：卡在内核里的子进程可以不理（`lsof` 撞失效网络挂载） | 仍在运行就不问；SIGTERM 不死则 SIGKILL；补覆盖 |
| 刚通电的下游 | `SnapshotBuilder` 三处消费 `hit.cwd`。其中「多个陈旧会话按活进程 cwd 消歧」因 `hit.cwd` 恒空**从未执行过一次**，测试零覆盖。0.99.1 之后它开始决定用户看见哪个会话 | 补回归；把物理/逻辑路径的语义差写下来而不猜着修 |
| shape 只能从终端拿 | `--harvest-shape` 是唯一必须开终端的诊断，而它正是修解析所需的证据。P0-3 因此空了两个版本 | 做进支持窗口一次点击 |
| 登录项从不校验 | `launchctl unload/load` 的返回值被 `_ =` 丢掉，开关无论是否注册成功都显示成功 | `launchctl list` 复核终态，进安全支持报告 |
| Focus 主线程等待 | `open -a` 走 `waitUntilExit()` 无超时，宿主 App 启动缓慢会冻结菜单栏 | 走带期限的 `ProcessIO` |

## 实测记录（lsof 退出码）

在一台 Linux 主机上跑同一份 `lsof`（同一作者的同一实现，退出码语义一致）：

| 情况 | 退出码 | stdout |
| --- | --- | --- |
| 活 pid | 0 | 正常 |
| 活 pid + 已死 pid | **1** | **活 pid 的路径照常打印** |
| 只有死 pid | 1 | 空 |
| cwd 不可读（他人进程） | **0** | `n/proc/<pid>/cwd (readlink: Permission denied)` |

第四行顺带证明 0.99.1 加的注解拒绝是**可达的** —— 那种情况 lsof 退 0，注解真的会进解析器。

这不是 macOS 上的直接观测。macOS 的 `lsof` 是同一实现，`-F` 与退出码语义相同；即便某天
不同，新写法也严格更保守：**多接受本来就该接受的输出**，不会少接受任何东西。

## 已知缺口（写下来，不假装没有）

1. **P0-2 的旧行为我没有证明过。** 「读一个运行中 Process 的 `terminationStatus` 会抛」
   需要一台 macOS 加一个真的不理 SIGTERM 的子进程才能证实。这一版能证明的是：这条
   路径现在有回归覆盖，且不再向运行中的进程要它没有的东西。修法本身零代价。
2. **物理路径 vs 逻辑路径。** lsof 给的是物理路径，Agent 会话文件记的是逻辑路径。
   `/Users` 不是符号链接，绝大多数情况相等；项目根在 symlink 之下时两者会静默不等，
   导致陈旧会话消歧退回按新旧。要真机证据才动 —— 这正是 0.96.1–0.97.2 四连发的教训。
3. **P0-0 仍未完成。** 它只能由用户在装了 Agent 的机器上产出。0.99.2 把它从「开终端跑
   CLI」降到「点一个按钮」，但**降低成本不等于拿到证据**。

## 为什么是这个顺序

P0-1 是 0.99.1 的直接续章：同一条通路，同一种失败形状（结果是对的，却在下一道门口被
丢掉），而且有实测。P0-4 是它的必然配套 —— 一条线通电之后，第一件该做的事是看看它接的
下游有没有人验过。

P0-5 排进 P0 是因为它解的是这个仓库**最老的一条阻塞**：P0-0 已经卡了两个版本，而卡住
它的不是难度，是「必须开终端」。把取证从命令行搬到按钮，是让 P0-3 有朝一日能被证据而
非猜测填满的最短路径。
