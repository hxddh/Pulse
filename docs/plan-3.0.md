# 3.0 — Mission Control / 指挥台（形态与能力的重生）

## 诊断（为什么 2.x 的路走到头了）

九个 2.x 版本都在同一个约束里打转：**形态是一块 448pt 的下拉玻璃**。采集端已经
相当强（秒级事件、计划、原话、磁盘效应、产出率自证），但托盘行的物理上限决定了
「看清楚」永远塞不进「扫一眼」的容器。

能力上更严重：**这是一个几乎没有动词的产品**。全部动作清单：忽略等待、稍后、
聚焦终端、远端批准/拒绝。用户的真实工作是同时操作一支 agent 舰队 —— 看谁卡了、
回答它的问题、派下一件活、验收它干完的东西。四件事 Pulse 只做半件。
**仪表盘，不是操作台。**

代码同样到期：`StatusStore` 4243 行神对象、`AgentRow` ~70 个平铺字段、
`PulseApp` 3179 行单文件 UI。好在有 900+ 条测试和九个版本的诚实规矩当契约。

## 三段走

### 3.0-α 地基（行为冻结）

只做编译器可验证的机械拆分，UI 与行为零变化，全量测试是冻结契约：

- `PulseApp.swift` 拆成场景文件：`TrayPanelViews.swift` / `SettingsViews.swift`
  / `SupportViews.swift`（β 的工作台会长在这一层旁边，先把这层理顺）。
- `StatusStore.swift` 尾部的独立工具类型（`TokenScope` / `DebugLog` /
  `LoginItem`）移出到自己的文件。
- **深拆 StatusStore / 重建 Session 实体在 α 故意不做**：接缝应该跟着用法走 ——
  工作台还没长出来之前拆引擎，是在猜接缝。等 β 明确了「窗口到底找 store 要
  什么」，再把那条真实的读取面拆成引擎边界。同理 S1（声明式适配契约）按 2.9
  写下的理由继续等真机产出率，不在 α 盲付。

### 3.0-β 工作台（形态）

- 真正的窗口（全局热键 + 托盘入口 + 「更多操作」入口），LSUIElement 不变。
- 左侧舰队面板（本机 + 远端，分组沿托盘规矩）；右侧会话检视器：
  时间线（recentTools + 活动事件）、完整计划清单、agent 原话、错误原文、
  **本地 git diff（只读）**。
- 原则更新并写进 EXPERIENCE：**「只有计数」是跨机器与托盘的规矩，不是产品的
  规矩** —— 工作台展示的是本机用户自己的仓库与会话记录：本地、只读、逐处过
  sanitizer、不出机器。托盘一个像素不变。
- diff 展示走 2.7 的 plumbing 纪律（read-only 动词集合扩 `diff` 输出到窗口时
  必须继续用不写 index 的命令族）。

### 3.0 正式（能力：回答 + 复盘）

- **回答**：等待行在工作台里读全文、写回复、发送。权限类沿用 Respond（HMAC、
  canOfferAllow、判断权不转移）；提问/续接类走 `claude --resume <session>` 派续
  —— 第一版保守实现：打开终端预填命令，真机验证后再考虑 headless。
- **复盘**：完成会话的检视器呈现「干成了什么」—— diff、清单终态、最后的话。
  验收在 Pulse，处置在用户自己的工具里；Pulse 永不代动仓库。
- 3.1 再做**派活**（新会话/远端派活，远端复用 respond 的签名通道）。

## 不变的脊柱

没测到的不许说；Waiting 唯一来源是 attention 协议；fail-open；0600；跨机器
只运计数与短名；判断权一寸不转移；能耗是硬约束；陈旧不冒充此刻。

## 风险与对策

- 盲写 Swift 的回归风险：行为冻结分段 + 每段全量测试 + 小 PR 快 CI 迭代。
- 工作台内容展示的泄露面：逐处 sanitizer、本地 only、diff 只读命令族。
- `--resume` 语义未经真机验证：保守版先行（预填终端命令）。
- P0-0（用户 10 分钟取证）仍只卡厂商侧富判决，不卡本计划。
