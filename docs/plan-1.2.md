# 1.2 计划 —— Substance / 行的实质

## 1.1 读完了，但只说出来一样

1.1 让摘要读完整份笔录，可**只有精确记录数上了界面**。同一份摘要里还躺着：

- 工具直方图（`Edit 12 · Bash 5 · Read 3`）
- 整场会话的错误总量
- **「同一个工具连着调了 N 次」的打转信号**

它们停在支持报告里，因为托盘一行只允许 4 个事实 —— 那是 EXPERIENCE 的硬规则，不该顺手破。
这一版是**认真地花掉那一格**。

---

## 打转是灯说不出来的那件事

一个 Agent 连着调同一个工具：**它在动，但没在推进。**

- 菜单栏灯表达不了：它在跑、活动时钟在走，所以是健康的绿。
- 窗口更看不到：重复发生在笔录中间那段 —— 1.1 之前从来没被读过的部分。

所以这是**只有读完整份文件才能产生、且用户一定想知道**的事实。它值那一格。

### 让位规则

| 谁优先 | 为什么 |
| --- | --- |
| **Waiting** 压倒一切 | 有人在问你问题，就不需要先听它怎么走到这一步 |
| **远端行**保留自己的叙事 | 远端笔录不在这台机器上，谈不上打转；「最后听到 / 失联」才是它能说的 |

### 明确不做

| 项 | 理由 |
| --- | --- |
| 让打转改变**灯色** | 状态编码上限 4 种，且「打转」不是 stalled —— 它有活动。发明第五种编码要单独论证 |
| 把工具直方图放上托盘 | 一行 4 个事实的规矩就是拿来守的。Details 才是完整证据的地方 |
| 「其它 N 个工具」 | 长尾直接丢弃。伪摘要读起来像信息，其实是噪音 |
| 从窗口文本复核摘要 | 窗口没读过那些字节，复核只能是猜 |

## 一条纪律：搬运，不重算

摘要的事实产生自**读完整份文件**，而窗口没有任何办法复核它们。所以 `SnapshotBuilder`
原样拷贝，任何「从窗口再算一遍确认」的想法都必须拒绝 —— 那不是校验，那是用看不见的
东西去质疑看得见的东西。

## 版本号规则改了

**发布时才分配号码，不再预留。**

Respond 的计划两次改名（1.1 → 1.2 → 无号），每次原因都一样：它阻塞于真机证据，而不阻塞的
工作先发布了。预留号码就是这件事的成因，所以它现在叫 `docs/plan-respond.md`，等证据回来
拿当时的下一个号。
