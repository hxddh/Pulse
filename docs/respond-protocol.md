# Respond Protocol v1 — answering this Mac's own agents

Respond delivers **the user's own decision** on a permission request to the
agent that raised it, from Pulse on the same Mac. Nothing leaves the machine:
no network, no server, no sync tool. Since 22.0 this is the whole protocol —
the remote half (per-host `requests.d/` and `verdicts.d/` trees, `secrets/`,
the shared `respond-secret.key`) was removed, and `LegacyCleanup` deletes those
directories once on the first 22.x launch.

Trust model first. The worst case of an attention event is a false lamp. The
worst case of a verdict is **an agent performing an action the user did not
approve**. So this path is held to a different standard: explicit opt-in, an
HMAC over every binding, single use, short expiry — any failure means "no
verdict", and every failure falls open to the vendor's own prompt (fail-open
for the agent, fail-closed for the verdict).

## Layout

`<pulse_dir>` is `PULSE_HOME` or `~/Library/Application Support/Pulse`.

```
<pulse_dir>/respond-local.key          # exists and non-empty = opted in
<pulse_dir>/respond.d/requests/        # the hook writes: the full request
<pulse_dir>/respond.d/verdicts/        # Pulse writes: the signed verdict
```

- `respond-local.key` is generated by Pulse (64 hex characters, `0600`) when
  the user switches on "Answer this Mac's agents from Pulse", and removed when
  they switch it off. **The key file is the switch**: no key, no hold, no
  verdict on disk. It never leaves this Mac.
- Both ends are local: the hook (`PulseBar --hook` via `pulse-hook`, or the
  optional `src/pulse_hook.py`) and Pulse.app. Files are `0600`, directories
  `0700`, reads are bounded (≤32 request files touched, ≤256 KB each), and
  each directory is capped at 64 files (oldest removed first).

## Request file

`requests/<request_id>.json`. `request_id` is sanitized before it becomes a
file name: only `[A-Za-z0-9._-]`, everything else becomes `_`, ≤120
characters, and a pure-dot name becomes `_`.

```json
{"v":1,"request_id":"toolu_x","agent":"claude","host":"thismac","session":"s1",
 "cwd":"/w","tool_name":"Bash","raised_at_ms":1,"expires_at_ms":2,
 "payload_b64":"<base64 of the verbatim hook stdin bytes>",
 "digest":"<sha256 hex of those same bytes>","truncated":false}
```

`payload_b64` is the vendor's hook stdin, **byte for byte**. Pulse recomputes
the digest over the decoded text; a mismatch marks the request `truncated`,
and a truncated request **never offers Allow** (Deny and "go look" are
unaffected). `host` is this Mac's label (`PULSE_HOST`, else the normalized
hostname); Pulse skips a request naming any other host, and one whose `agent`
is not a known `AgentID`.

## Verdict file

`verdicts/<request_id>.json`, written by Pulse:

```json
{"v":1,"request_id":"…","digest":"…","agent":"claude","host":"thismac",
 "allow":true,"decided_at_ms":1,"expires_at_ms":2,"hmac":"<hex>"}
```

HMAC-SHA256 with key = the raw bytes of `respond-local.key` (trailing
newlines trimmed), over the canonical string:

```
"v1\n" + request_id + "\n" + digest + "\n" + agent + "\n" + host + "\n"
       + ("allow"|"deny") + "\n" + decided_at_ms + "\n" + expires_at_ms
```

Pulse writes a verdict only for the request that was on screen (the click
carries its id and digest), refuses Allow unless the full request was shown
(`canOfferAllow`), and gives each verdict a 90-second life.

## When the hook holds

All of these, or it exits 0 at once and the vendor's prompt appears:

1. The event is a `PermissionRequest` (an `AskUserQuestion` is a question and
   never held) from an agent whose `respondReach` is `hookSite` (Claude).
2. The verbatim stdin is non-empty and carries a `tool_use_id`.
3. `respond-local.key` exists and is non-empty.
4. **The prompt is not in front of the user.**
   - The native receiver holds when nobody has touched this Mac for
     `PULSE_RESPOND_AWAY_SECONDS` (default 120, clamped to [30, 3600]), or
     when someone is here but the frontmost application is provably not an
     ancestor of the hook (`PromptVisibility`). Unknown is not proof: a
     question it cannot answer lets the request straight through.
   - `pulse_hook.py` cannot see windows. It holds only when it can read the
     idle age (`ioreg` `HIDIdleTime`) and it is at least the away threshold;
     a present user, or an unreadable idle age, never holds.

The hold writes the request, then polls `verdicts/` every 250 ms until
`PULSE_RESPOND_MAX_HOLD_SECONDS` (default 60, clamped to [5, 300]).

## Claiming a verdict (hook side, all must hold)

1. **Exactly once**: the hook renames `<id>.json` to `<id>.json.used` first,
   and only a successful rename may be read. A claimed verdict that fails any
   check below stays consumed.
2. The HMAC verifies with the local key (constant-time comparison).
3. `request_id`, `digest`, `agent` and `host` equal the held request's.
4. Not expired: `now < expires + 5 min` and `decided − 5 min ≤ now`. Both
   ends read this Mac's clock, so the tolerance only matters if the clock is
   adjusted mid-hold.
5. `allow` additionally requires `truncated == false`.

Anything else is "no verdict": keep waiting, then time out. The hook always
exits 0 and prints nothing on a timeout. On a verdict it prints the decision
shape Claude Code consumes:

```json
{"hookSpecificOutput":{"hookEventName":"PermissionRequest",
 "decision":{"behavior":"allow"|"deny","message":"Answered via Pulse from <host>"}}}
```

If a CLI version does not honour this shape the verdict is silently ignored —
fail-open, harmless, and the one real-machine confirmation 2.0 still lists.

## What a verdict's fate means

`claimVerdict` renames before reading, so Pulse can report what happened
rather than what it did: **waiting** (written, in time), **taken** (the
`.used` remnant exists), **expired** (the deadline passed untouched — the
vendor prompt already appeared, the designed failure). Requests are swept one
hour past their expiry; `.used` remnants after an hour.

## Frozen between the two hook implementations

`PulseHookReceiver` / `RespondSpool` (Swift) and `src/pulse_hook.py` implement
this identically — change both or neither: the file names and sanitizing, the
schema, the canonical string, the skew rule, the 64-file cap, the cleanup
grace, the poll interval, the hold clamps, and the decision JSON.
`scripts/respond_hook_check.py` (a `gates.sh` gate) re-derives the HMAC from
the canonical string and proves: no key → no hold; a present user or an
unknown idle age → no hold; the retired shared key → no hold; tampered,
mis-bound, expired, reused or foreign-key verdicts → no adoption; timeout →
silence and exit 0.

## Relation to Attention

A request does not replace the attention raise — the lamp lights as always.
Respond only adds an action once it is lit. `attention-protocol.md` says
"whoever can write the inbox can light the lamp"; this protocol's equivalent
is: **whoever can write `verdicts/` still cannot approve anything** — without
the key there is no HMAC, an edited request does not match its digest, and
yesterday's verdict has expired.
